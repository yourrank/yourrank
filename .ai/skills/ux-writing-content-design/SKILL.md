# UX Writing / Content Design

Labels:
Use specific actions. Prefer `Save API key` over `Continue`.

Errors should answer:
1. What happened?
2. What can the user do next?

Status:
Translate technical state into user meaning.

Help:
Prefer inline explanation near the decision. Essential knowledge should not depend on tooltips.

Empty states:
Explain why there is nothing, whether that is expected, and what useful next step exists.

Tone:
Preserve product terminology and `DESIGN.md`.
Clarity beats cleverness.
